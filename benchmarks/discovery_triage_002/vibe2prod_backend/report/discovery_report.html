Architecture Context

Python FastAPI monolith with 7 modules. The API layer exposes REST and SSE endpoints protected by JWT middleware. Business logic lives in tier1 (orchestrator, indexer, scanner, reporter). External integrations (GitHub, OpenRouter/LLM, Supabase) are in services. Sandbox execution isolates repository analysis. Global in-memory state is used for SSE event buses and webhook replay detection, creating scalability and reliability risks. The architecture lacks a clean service abstraction layer — routes directly import database clients and domain objects from tier1.

critical reliability Unbounded In-Memory SSE Event Bus Causes Memory Leak and Horizontal Scaling Failure
The global `event_buses` dictionary in api/routes/_sse.py stores scan events indefinitely. Entries are added when a scan starts (audit.py) but never removed after the SSE stream completes or the scan finishes. This causes unbounded memory growth under sustained load. Additionally, in horizontally scaled deployments, clients connected to different instances will miss events since each instance maintains its own in-memory store. Multiple workers (security, quality, architecture across both waves) independently flagged this as critical/high severity with high confidence.
